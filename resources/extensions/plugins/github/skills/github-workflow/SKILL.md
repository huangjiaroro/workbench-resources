# Git 与 GitHub 工作流

先确认仓库、目标分支和本次授权，再用 `git status` 与 diff 查清原有改动。按指定文件暂存和提交，核对提交内容及 SHA。推送和创建 PR 时使用 [GitHub 插件入口](../../WORKBENCH-TOOLS.md)，明确选择连接、目标仓库及源分支，按授权执行。

## 并行工作

同一工作区足以承载本次改动时直接使用。多人确需并行修改同一仓库时，负责人先按模块和接口分工，为每个开发任务在获准的可写位置准备独立分支与 worktree。共享接口先确定契约，隔离构建和缓存输出，各任务记录 base、head 和验证结果。正式运行服务与开发测试使用各自的目录和数据。

集成人员按依赖合并，处理冲突并运行受影响测试。清理前核对任务完成、分支成果已保全和工作区实际状态。删除分支、强推或合并目标主分支按任务授权执行。

## 审查和交付

开 PR 前核对已推送的提交、目标分支、验证结果和正文。根据实际 PR 编号读取会话和行内审查意见，按准确提交核对 CI 状态和失败日志。返修提交推到原分支，再查同一 PR 的当前结果。

回报仓库、分支或 worktree、提交 SHA、已执行验证、PR 链接和检查状态。有未提交的改动或未知远端结果时，注明最后确认到哪一步，并按工具说明查询原操作。
