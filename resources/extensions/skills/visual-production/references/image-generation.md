# 四类基础设定板与定点补图

输入为明确素材/变体、有效设计、当前用途和真实参考。每个实体生成一张完整设定板，板内不同视图仍是同一人物、服装、空间或道具；四类素材各自独立。

## 四类设定板的具体规格

通用风格、负向约束和真实检查要点见[共通 Prompt 约束](image-prompt-templates.md)。**具体专业版式只由对应类型规则维护**，实际出图前读取相应文件：

| 类型 | 类型专有方法 | 使用重点 |
| --- | --- | --- |
| `character` | [人物设定板](templates/character-board-prompt.md) | 面部身份、身体结构、正侧背一致性 |
| `costume` | [服装设定板](templates/costume-board-prompt.md) | 造型、剪裁、材质与人台正侧视 |
| `scene` | [场景设定板](templates/scene-board-prompt.md) | 空间结构、地标、布局及多视图一致性 |
| `prop` | [道具设定板](templates/prop-board-prompt.md) | 独立造型、侧顶视、重要细节与尺寸 |

正式设定板统一采用 16:9 横向格式。名称、分格和辅助视图只用于设计，不得混入实际镜头画面。具体细节随类型规范执行；不因旧样例与当前正式设计冲突而擅自改变人物身份、空间结构或道具数量。

## 标杆与范围

按获准范围准备全局基础素材或单集缺口，已有适用项复用。主角标杆用于统一风格与身份，采用和用户确认遵循组织方法及当前授权。生成、作者自检与正式采用分别记录，产物位置从组织约定解析。

## 执行

1. 读取真实设计和已有媒体，核对精确版本与适用形态。全身衣着、背面结构或尺寸依据缺失时先交视觉设计补齐；出图阶段不临时发明新设计。
2. 读取对应固定规则，将模板中的全部占位内容换成真实设计。保存图像规格、实际中文 Prompt、参考顺序及各图用途；不只写“按模板”，不擅自省略名称、辅助视图或尺寸参照。批量规模与并发服从实际工具或连接容量；没有容量依据时串行。
3. 按当前组织与工单规定的出图优先级，选择本员工原生出图能力或已启用且获准的插件，读取所选入口的真实说明；要求原生优先时，先使用原生能力，受限后才使用插件并记录原因。Codex / Antigravity 原生工具与插件 CLI 分别核对。真实调用与返回才算生成，不用旧仓库 CLI、猜测 URL 或文字承诺执行。
4. 核对实际生成文件、哈希与生成来源。未知提交先查询原结果，不换键重复出图。
5. 逐张实际查看整板和各子视图：查左右布局、必需视图、全身裁切、名称、跨视图身份/结构/状态，以及当前承重属性。格式错误也须修复，不能仅因“角色好看”或“五金可见”判通过。
6. 在对应资产正式目录保存当前设计、实际图片与完整生成 Prompt（包括参考顺序和用途）；归档与采用遵循组织规则。在唯一 registry 登记实际对象及当前成果路径，design.md 记录规格与自检范围。单项自检就绪即回传成果文件路径与实际素材，由团队交接复用，不等待整包说明。没有可用看图输入时保留“已生成，视觉待检查”。

## 补图与替换

基础设定板不自动混入情绪、换装、天气、损伤或开合变体。正文/Shot 确实需要新状态、局部细节或构图锚点时，先判断是否仅为**临时剧情状态辅助图**：若是，将需交付的真实图与实际 Prompt 存于本集 references 对象目录，说明需求、来源、对应 Shot、真实媒体路径与用途，交视频制作人记录在本集 `video-production` 中；**不在 `asset-registry` 创建正式资产或正式变体，也不把临时状态图当成新设定板**。仅在外观结构或稳定视觉设计确实产生独立版本（如重大变身、独立换装）时，才由视觉设计师生成新的完整标准设定板并登记正式变体及适用范围。

单视角、特写或场面图可以作为明确需求的补充，不能冒充已完成基础设定板。能力无法完成既定版式时回传具体未达项和影响，不自行降规格。替换后实际查看新版本，不凭旧图存在认定成功；版式例外只能来自当前用户的明确要求并记录依据。

角色有发声需求时另组织真实音色与试听；voice_id、图片或未试听配置不等于音频参考已经准备。
