# 整体故事设计

按 [SKILL.md](../SKILL.md) 的 A 阶段依次独立完成 A1–A5，分别在员工自己的工作空间保存独立工作稿；每一步先回读已保存的前置结果。A6 整合并保存完整工作稿，独立回读与检查，修正并复查后才写正式 `project-design.md`。以下是最终设计稿结构，不是一次性填表任务；章节内可使用自然语言、表格或列表，按故事需要决定深度。括号内的提示与完成判据用于设计，不作为空泛内容抄入产物。

## A1｜故事核心

- 核心前提与戏剧表达：（这个故事为何值得讲，主人公面对什么特殊处境）
- 激励事件：（什么事件迫使主人公行动，不能维持原状的原因）
- 主角欲望、主要矛盾与代价：（追求什么，什么力量持续阻碍它，失败或成功要付出什么）

## A2｜人物与长期冲突

| 承重人物 | 目标与动机 | 手段、制约与知情边界 | 对抗关系与关键选择 | 弧线方向 |
| --- | --- | --- | --- | --- |
| | | | | |

涵盖主人公、主要对手及持续改变主线的重要人物。说明目标为何冲突或相互依赖、怎样相互施压、失利后如何改变策略。人物变化可以是成长、堕落或坚持；不为无承重作用的小角色补造完整传记。

## A3｜整体故事结构

| 关键阶段／事件 | 人物行动与选择 | 对抗、后果与下步因果 | 关系、认知或处境变化 |
| --- | --- | --- | --- |
| | | | |

写清关键转折如何由人物选择、反制与代价导致；高潮怎样兑现前面的因果、关系与伏笔；结局落实人物弧线与核心矛盾。阶段数量按故事需要，不按固定幕数或节拍配额。

## A4｜系列引擎

- 持续事件生成机制：（参与的人物、约束、可持续的行动机会）
- 冲突变奏：（不同目标、策略、反制与后果，如何避免单元重复）
- 升级与闭合：（优势为何不能立即解决全部矛盾，压力如何累积，何时转向或结束）

单一作品无需系列引擎时注明不适用。身份信息差、类型标签或“每集有爽点”不能代替机制。

## A5｜整季与分集结构

| 阶段／单元 | 阶段目标与主要事件 | 人物变化与前后因果 | 信息揭示、伏笔与兑现 |
| --- | --- | --- | --- |
| | | | |

| 分集范围 | 本集承担的独立作用 | 主要因果变化 | 结尾及下集承接 |
| --- | --- | --- | --- |
| | | | |

按项目实际规模设计整季、单元及分集脉络；优先明确本轮需要的分集及其前后承接，不要求提前写完全部单集或把分集梗概写成正文。必要 Story Unit 细化需求与影响范围在相应章节注明，由 B3 处理。

## A6｜完成判据（供自检）

- A1–A5 具有具体可追溯内容，核心因果、对抗与选择、引擎与分集相互成立。
- 对承重设计的重要取舍，在对应章节保留采用理由、成立条件和代价；确有实质候选时记录取舍，不为每个细节创造多套方案。
- 用户要求、专业采用方案、未来规划、角色知情与未采用候选区分清楚；未解决且影响下游的问题写明影响范围。
- 采用理论应体现实际人物、事件或机制上的设计选择，而不是术语标签。
- 已有有效设计可引用准确位置与版本，局部修订只更新受影响章节。核对完成后保存设计稿，B 阶段据此整理正式成果。

完成判据供自检，不复制到正式产物；不另建阅读日志或步骤报告。
