# 必要承重单元：戏剧价值与机制成立

当案件、游戏、竞赛、骗局、身份局、跨事件布局等机制一旦失效会导致关键剧情大段重写时，才建立一个 story-unit。按完整机制命名 CASE / GAME / LAYOUT 或适用类型；不按每集、每条线索或每个普通冲突建文件。

## 先让它值得看

明确该单元为什么会吸引观众：谜面、困局或规则究竟有何特别之处；人物为什么必须卷入；观众期待的发现、交锋或解决是什么；揭晓如何重新解释前面的信息，或使人物付出代价、作出选择、改变关系。复杂不等于精彩，纯逻辑自洽也不等于有戏剧价值。

核心创意可以来自用户与主创的深入讨论、研究员的候选方案或故事作者独立设计。尊重已确认的谜面、真相和反转，不把讨论中未被采用的猜测写成正式事实；保留编剧对细节和因果实现的专业空间。

## 再让机制经得起推演

承重单元需要足够明确地说明：真实过程与最终结果、各方目标/资源/所知、必要的时空和行动条件、信息如何被呈现或误读、关键线索或规则、可能的理性反制与竞争解释、揭示或结算如何成立，以及会改变结论的失败边界。

按实际机制自然组织，不强制八项评分表或固定线索数量。悬疑单元尤其要分清真实真相、角色推论和观众得知的顺序；游戏或布局单元则须把规则、行动空间与关键后果说明白。不能为了反转临时补充决定性的隐藏规则或让对手失去合理判断力。

研究员可在明确授权下研究或设计具体机制，故事作者负责与整体人物、情节和蓝图衔接；是否安排独立审查，由组织根据难度、缺口和任务决定。只调查会改变机制成立或故事选择的未知，不例行穷尽所有专业细节。

## 与蓝图双向校正

单元既可以先于蓝图，也可以在蓝图发展中被识别；两者发现冲突时回到对应创作层修正，而不在单集正文中临时圆场。无法成立且需要更改用户锁定的核心创意、人物身份或终局时，向主创说明具体影响，交其协调。

正式单元用稳定 `unitId` 维护完整推演。故事作者只将真正影响人物选择、后续因果、揭示边界和结果的结论回写蓝图与必要的 `canon`；不复制技术说明。未解决的关键机制只阻断直接依赖它的写作，已成立、未受影响的范围可以继续。
