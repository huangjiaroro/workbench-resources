# Production：Scene / Shot ↔ 技术 Clip 完成范围与来源索引

唯一正式文件仍是组织 `video-production` 产物，即 `episodes/EP{episode}/production/production.md`。上部索引包括本轮要制作的**全部导演 Shot**（未生成也列出），按 Scene → Shot 顺序；一个 Clip 可映射连续多个 Shot，一个 Shot 也可对应多个技术 Clip。导演成果只读；从逐 P 表的 Shot ID 及衔接识别实际镜头，一个连续 Shot 在索引中登记一次，内部依各行自然时长与并行关系组装。由对应 P4 片段取得对白及说话人并对照锁定 Script，不修改导演文件或正文。

## 顶部：全范围覆盖索引

| Scene | Shot ID | 当前导演 Shot 版本 / 哈希 | Clip ID / 实际生成范围（Shot 局部） | 实际视频路径 / 哈希 / 时间 | 关键帧索引（路径、源内时间） | 生成状态 / 后期待办 |
| --- | --- | --- | --- | --- | --- | --- |
| SC01 | S001 | Shot Plan 版本或 SHA256 | C001：S001 局部 0–2.5s | `clips/c001.mp4` / SHA256 / 源内 0–2.5s | `frames/c001_t2.png` / 00:02 | GENERATED；台词是否完整待后期 |
| SC01 | S002 | 同上 | C001：S002 局部 0–2.5s | 同一 `clips/c001.mp4`，源内 2.5–5s | `frames/c001_t4.png` / 00:04 | GENERATED |
| SC01 | S003 | 同上 | — | — | — | PENDING |

上述均为**字段格式示例，不代表真实媒体存在**。一次 Clip 多 Shot 必须在相应 Shot 行写同一 Clip，带可定位的源内范围；不能用一个已生成 Clip 代表尚未完成的其他 Shot。一个 Shot 分为多个 Clip 时，逐一登记其 Shot 源内区间、对应 Clip 区间和连续性要求，不增加硬切。

状态用 `PENDING`（未生成）、`RUNNING`、`GENERATED`（真实文件已存在，内容未验收）、`FAILED`、`BLOCKED` 等客观值。**不得仅根据生成成功或抽帧成功标记视频/音频 PASS、导演意图已实现或整集已完成。** 视觉/声音待办留给后期按真实素材检查。

## 下部：技术生成尝试

按 Clip ID 或任务 ID 维护可追溯的真实记录，无须另建文件：

```markdown
### Clip C001 / 尝试 1（Scene SC01）
- 覆盖导演 Shot：S001 + S002；对应已审定 Shot Plan 版本/哈希：...
- 分组依据：连续相邻 Shot 的实际表演范围；需拆分时记录组织／工具时长上限或其他实际限制，以及自然承接位置
- 模型 / 模式 / 技术生成秒数：按真实插件请求与回执
- 实际 Prompt：...
- 输入绑定：实际资产/图片/视频/音频、来源版本、用途、模式与对应标签
- 任务 ID、回执、失败/重试：...
- 输出媒体：真实路径、实际时长、哈希；若无输出明确 FAILED/BLOCKED
- 抽帧：源视频时间点、图片路径、哈希；观察记录：实际查阅状态、观察内容及来源版本
- 状态：GENERATED（未作逐段内容验收）；声音、裁剪、组装等后期待办：...
```

导演镜头结构、机位或切点需要变更时交主创协调导演；剧情、关键动作和对白内容变更由主创协调编剧修订并重新采用，导演与制作人不自行删改或精简。已有 Clip 更换时更新其对应 Shot 的版本/关键帧索引，保留来源追溯，并按[连续性状态版本规则](continuity.md#状态版本)核对真正依赖旧结果的后续范围。后期只基于明确 `GENERATED` 文件和真实制作进度组织成片，不得把待生成镜头视作已经覆盖。
